# 需求发现与证据

## 从决策缺口开始

先确定要回答的问题，例如“审批耗时主要在哪里”“某需求是普遍问题还是单客定制”。先读已有资料再补检索。不把联网搜索等同于用户研究，也不强制每个小改动调查市场规模。

新方向常需竞品/替代方案、用户任务、行业变化和技术约束；深度取决于它是否影响决策。找到能解释关键取舍的证据后收敛，保留未证实与相互冲突的结论。

## 证据记录

在 `analysis/03-evidence-ledger.md` 记录：

| 字段 | 内容 |
| --- | --- |
| ID 与类型 | `E-001`；事实、推断或假设 |
| 内容 | 观察到了什么；推断与事实分行记录 |
| 来源与时间 | 原始文件/记录位置或 URL、材料日期、访问日期 |
| 样本与边界 | 对象类型、人数、数据窗口、地域、产品版本和偏差 |
| 信心与反证 | 支持程度、矛盾来源、不能得出的结论 |
| 决策用途 | 对应问题/需求、需要补的验证 |

公开事实优先用官方文档、公告和原始研究；社区经验用于提出假设及补充案例。多个转述同一消息的页面不算独立佐证。区分“用户提供的内部记录”和“代理独立核验”。付费墙、登录限制或抓取失败须记录限制，不把标题当全文证据。

## 访谈与反馈

JTBD（待完成任务）的写法：在某情境下，用户希望完成什么，从而获得什么结果。追问最近一次实际经历：触发、步骤、现用办法、耗时/损失、卡点及替代选择。避免“如果做这个你会不会用”式诱导。

准备访谈时交提纲和招募条件；没有真实记录就不能生成“用户原话”。整理反馈时按任务和情境聚类，保留样本差异、负面证据及未覆盖人群。身份信息按需匿名化，外部文档只保留可分享结论。

## 竞品与替代办法

比较相同角色的同一任务，覆盖直接竞品、间接替代及 Excel/人工流程。表格包含产品/版本/地区、任务流程、定价口径、优势、缺口、证据日期和启示。官方宣称与亲自验证分开。

结论回答“用户为什么改用本方案，以及付出什么迁移成本”。不以功能勾选数量或主观总分替代差异化判断。

## 假设验证

高影响未知项用 `H-001` 等编号关联证据和需求。可用 OST（机会解决方案树）连接目标、问题、方案与实验。

| 类型 | 适用验证 | 应保留的限制 |
| --- | --- | --- |
| 问题存在性 | 实际经历访谈、工单、行为数据 | 访谈不是市场普及率 |
| 可用性 | 任务式原型测试 | 能操作不等于愿付费 |
| 商业可行性 | 范围明确的试点、购买行为、实施记录 | 单客成功不等于可规模化 |
| 效果 | 适用时的随机对照实验或分批试点 | 小样本/前后对比不直接证明因果 |
| AI 交付质量 | 脱敏评测集、错误分类、人工验收和成本测算 | 演示样例不代表总体准确率 |

计划写清方法、对象、主指标、成功/失败/不确定条件、责任角色、成本和下一步。阈值说明依据；没有基线先采基线。不擅自联系用户、发问卷或启动线上实验。

## 无法取得证据时

说明未联网、样本不足或权限限制，完成已有材料支持的草案。待核实项写入证据表和决策页，说明它阻止方案确认、排期还是上线。研究计划完成与研究结论已验证分别汇报。
