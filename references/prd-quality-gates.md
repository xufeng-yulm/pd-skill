# PRD 交付与复审标准

轻量和标准模式采用相同的决策质量要求，只改变拆分方式。模板生成不算需求完成，文件齐全不代表已评审。

## 需求追踪

用稳定编号连通 `E-ID → REQ-ID → BR-ID → AC-ID → MET-ID/版本`。允许一对多和多对多。新增需求同步需求池，范围变化同步规则、验收、数据和上线计划。

每条需求包含角色及任务、前置条件、入口、成功/失败路径、权限、状态变化、依赖、优先级理由及验收结果。只补相关字段，不要求每个按钮单独写文档。

**教学示例，非真实项目事实：**

| 编号 | 描述 |
| --- | --- |
| REQ-001 | 经办人提交报销后可查看状态，重复提交不生成重复单据 |
| BR-001 | 同一提交标识只产生一个单据；用户只能看授权范围内数据 |
| AC-001 | Given 经办人已登录且输入有效；When 连续提交同一请求；Then 返回同一单据且只生成一条记录 |
| AC-002 | Given 无访问权限；When 请求单据详情；Then 明确拒绝且不返回单据内容 |

追踪编号不替代正文：只写“见 AC-001”却没有可观察结果仍不合格。

## 规则与异常

按需要检查权限矩阵（角色×操作×数据范围）、状态迁移（起始状态/事件/条件/目标状态）、字段校验和边界。涉及真实动作时覆盖重复提交、并发、超时/部分成功和恢复。支付、审批等流程区分失败与结果未知，不假定重试不会重复执行。

技术章节说明系统边界、输入输出、现存依赖和待研发确认的建议。没有工程证据时不写成既定接口或微服务架构。

## 数据与验证口径

| 内容 | 最低要求 |
| --- | --- |
| 指标 | 定义、分子/分母、单位、去重、时间窗/时区、过滤条件、数据源、基线、目标及负责人 |
| 埋点 | 事件名、触发时机、触发端、属性类型、去重、关联需求/指标及验收办法 |
| 实验 | 假设、对照、随机化单位、样本量依据、周期、主指标、护栏、停止规则、不确定结果处理 |

目标为建议值时说明依据和待确认状态。留存注明同期群与回访行为，金额注明退款/优惠/税费口径。A/B 实验（随机对照测试）不适用时说明试点方法及局限。

## 三类交付状态

| 状态 | 判定依据 | 不足时 |
| --- | --- | --- |
| 可评审草案 | 问题、证据/假设、取舍、范围、成功标准明确 | 列缺口，不伪造调研或确认 |
| 可供研发估算 | 需求/规则/异常/验收可追踪，依赖与边界可判断 | 标记未定接口、估算和决策责任角色 |
| 可上线放量 | 实际测试、业务验收、监控、回退及运营准备已核实 | 只称上线计划就绪，不称条件已通过 |

PRD 评审按影响排序，输出严重程度、位置/需求编号、后果及具体修改建议，不只给总分。无实际记录时不能把“已批准”“已冻结”当事实。

## 上线与复盘

上线计划写人群/租户、观察窗口、放量与停止条件、回退及责任角色。按实际业务选择试点、培训、客服和迁移准备。

复盘比较目标、实际、同期/历史基线、异常因素、反馈、实际成本和下一决策。观察时间按业务周期选择，T+1/T+7/T+30 只是示例。记录大促、节假日、渠道及人群变化，不把所有改善归因于功能。

## 行为验收场景

修改 Skill 后用这些场景检查执行是否合理；模拟产物放临时目录，不写外部系统：

| 输入 | 应表现出的行为 |
| --- | --- |
| “只补后台批量导出需求，不做原型” | 轻量 PRD，包含权限/容量/部分失败/验收，不追加全套材料 |
| “老板要加 AI，暂无用户数据，也不能联网” | 标假设、比较适用方案、设计验证，不编造搜索和访谈 |
| “大客户要插单，销售说金额很大” | 核实承诺，比较标准/配置/定制及机会成本，不自动列 P0 |
| “小程序支付成功但页面超时” | 区分订单/支付状态、查询恢复、重复回调和点击验收 |
| “发布到已指定的飞书节点” | 继承已有授权与目标，只补真正缺失信息，保留逐篇结果 |
| “已有上线数据，帮我复盘” | 检查指标/样本口径、区分相关/因果、给出下一决策 |
