# 产品方法：按决策选择

方法用于解释取舍，不要求全部使用。来源见 [pm-source-map.md](pm-source-map.md)。下面的场景选择是本项目整理，不代表原作者的统一标准。

## 1. 选择方法

| 决策问题 | 推荐方法 | 避免 |
| --- | --- | --- |
| 用户真正要完成什么 | JTBD（待完成任务）+ 最近一次真实经历访谈 | 凭空生成画像和引语 |
| 什么问题值得探索 | OST（机会解决方案树）：目标→机会→方案→验证 | 把功能清单换成树形排版 |
| 小需求先做哪个 | 价值/投入 + 证据强弱 | 没数据仍给精确分数 |
| 多个可比机会如何排序 | RICE | 混合客户数/交易数、故事点/人月 |
| 固定版本如何保范围 | MoSCoW：必须/应该/可以/本次不做 | 所有需求都是“必须” |
| 基础能力还是惊喜体验 | Kano（基本/期望/魅力等需求） | 把主观分类当用户调研结论 |
| 大客户插单怎么处理 | 硬约束 + 复用价值 + 全周期成本 + 机会成本 | 单一客户金额决定一切 |
| 上线是否有效 | 漏斗、同期群、适用时的对照实验 | 把前后变化直接解释为因果 |

## 2. 机会评估与聚焦

先写问题、用户、现有替代办法和为何现在处理，再比较方案：

1. 用户任务与痛点证据，关联 `E-ID`。
2. 用户结果与商业价值；谁使用、谁决策、谁付款。
3. 适用的可选路径：流程优化、人工试点、采购/集成、自建或暂缓。
4. 最大的价值、可用性、商业可行性、技术可行性假设。
5. 推荐做/验证/延后/停止及理由；什么证据会推翻决定。

聚焦判断保留一句话价值、核心任务、不做清单和端到端体验。重大方向可用简短发布说明检验价值表达，小改动不强制写新闻稿。不把固定访谈人数、周期或信心阈值当成立项门槛。

## 3. RICE 的计算口径

`Score = Reach × Impact × Confidence / Effort`

| 因子 | 口径 |
| --- | --- |
| Reach 触达 | 同一时间窗内的用户数、客户数或事件数；一次排序统一单位 |
| Impact 影响 | 对同一目标的影响尺度，可用 0.25/0.5/1/2/3，说明依据 |
| Confidence 信心 | 用 0–1 计算，80% 写为 0.8；关联证据 |
| Effort 投入 | 正数，统一人周或人月；包含产品、设计、研发、测试、实施等成本 |

**演示数据，非真实调研：** 同季度触达 200 客户，影响 2，信心 0.8，投入 4 人月，分数 `200 × 2 × 0.8 / 4 = 80`。80 是排序值，不是收益或成功率。

- 投入为 0、未知或只有 S/M/L 时，先估算或定性比较。
- 分数接近或波动大时做保守/乐观比较；排序随假设变化时先补证据。
- 低信心提示需要验证，不自动等于取消。已确认的依赖、合同或关键风险可改变排序，记录理由和决策人。
- 评分不能把销售口头承诺变成已确认硬约束。

## 4. 需求池与评审

记录问题、来源证据、影响用户、价值、优先级依据、依赖、负责人和版本。标签由团队定义，可采用以下**示例约定**，并与缺陷严重度区分：

| 优先级 | 示例含义 |
| --- | --- |
| P0 | 本次交付阻塞项，必须说明截止、影响和依据 |
| P1 | 达成本期目标的主要能力 |
| P2 | 可延后，不破坏当前核心任务闭环 |

对大客户插单，明确收入/合同依据、复用面、实施和维护投入、被挤出的需求；输出接受/配置满足/定制/延后/拒绝及原因。变更同步需求池和决策页，不静默扩大范围。

## 5. 路线图与容量

Now/Next/Later（当前/接下来/以后）表达确定性，不强制对应季度。

- Now：目标、范围、负责人、容量、依赖和验收明确；日期区分建议与承诺。
- Next：方向成立，写进入 Now 的条件。
- Later：写触发信号，不虚构日期。
- Not Building：写不做理由及重新评估条件。

不要把“最多 3–5 项”当通用硬上限；按工作量、并行能力和关键路径控制在制工作。产品、设计和研发共同确认估算。

## 6. 市场与商业测算

TAM（总潜在市场）、SAM（可服务市场）、SOM（可获取市场）采用相同时间、地区、币种及收入/用户口径，通常满足 `SOM ≤ SAM ≤ TAM`。

- 自上而下保留统计范围；自下而上用潜在客户数×合理客单价，并计入触达、成交和交付能力。
- SOM 由销售、渠道、赢单率、容量和竞争决定，不存在通用的“SOM 必须小于 SAM 的 30%”。
- 内部效率工具直接估算工时、错误成本和投入，不强行套市场规模。
- 写假设区间、数据年份及反证，不按任意固定渗透率判断产业阶段。

## 7. 指标与实验

北极星指标应反映持续获得用户价值，输入指标解释变化，护栏防止代价失控。GMV（成交总额）、收入、回款和利润口径不同，激活、日活和留存也不能混用。

实验预先定义主指标、随机化单位、样本需求依据、周期、护栏和停止规则。ToB 客户少或群组互相影响时可采用试点，说明因果推断局限。不虚构样本量、显著性和提升数据。

## 8. 体验与沟通

减少无关输入和中断，提供及时反馈、返回与异常恢复路径。通知遵循用户选择、紧急程度和静默时段，不默认全部安排在工作时间之外。授权、付费和营销订阅不靠预勾选诱导。

交接写“结论 + 依据 + 未决事项 + 责任角色 + 下一动作”。发现延期或指标异常时说明影响和修正方案，不隐藏未知。
